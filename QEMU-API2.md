# API2 offline milestone (dev.20)

SuperBIOS is Tier7's manager. Ordinary OpenOS CDs are unrelated. This release adds a parallel Java8 data/protocol API and new optional OCVMIntegration-offline-dev.2.jar, not a QEMU executable or working guest backend. Use one optional addon: dev.2 requires main dev.20+, while the preserved dev.1 addon remains API1-compatible. Never co-load the two addons with the same modid. Ordinary tiers and the accepted case/BIOS UI remain unchanged.

API1 classes, provider symbols and the old offline status are unchanged. API2 lives in li.cil.oc.api.vm.v2. ProtocolV2 registers one explicit qemu-tcg provider, advertises synthetic frame/input capabilities and always denies guest execution. No automatic executable discovery occurs. Host.declared normalizes injected Windows/Linux/macOS and amd64/x86_64/aarch64/arm64 strings; BackendProfile carries independent host/guest ISA, machine/version, CPU, firmware hash/licence and pack hash. These are unqualified declarations; no host/guest profile is certified or launched.

ProtocolV2.decode accepts exactly twelve flat JSON fields: version=2, session, correlation, world, case, owner, package, generation, sequence, epoch, canvas and operation. operation is STATUS, START, STOP or REVOKE. It caps UTF-8 input at16KiB before decoding, rejects malformed UTF-8, duplicate/unknown/missing fields, noncanonical UUIDs, wrong types, non-integer/overflow values and trailing data. Canvas is64lowercase hex. Generation/sequence arepositive; epoch is nonnegative. There is no arbitrary body, path, CLI/QMP, shell or URL field. Schema1's old character-count limit is preserved; API2's byte gate is additional.

SessionV2 is constructed on and confined to one authoritative dispatcher. A future transport must marshal requests there; a packet's identity is never server authorization. Pool admits at most32 configurable sessions globally and2per world/case; every request rechecks an injected authorizer, all identities, session, generation, epoch and canvas fingerprint. Sequence must increase exactly once. At most32 correlated requests may be outstanding; admission reaps correlations older than2seconds. The implemented transport completes synchronously. Async reply timeout validation is not an implemented wire feature. Sessions expire after30seconds idle or clock rollback. The integration must call Pool.tick; no thread/listener is spawned. Revoke clears pending requests and invokes at most3 cleanup hooks. A layout/authorization generation change requires a fresh session. The current in-memory implementation is neither a durable capability store nor real server/game integration.

OfflineAdapterV2 implements the Transport seam. STATUS returns OFFLINE_PROVIDER; START/STOP return RUNTIME_DISABLED; REVOKE acknowledges and revokes. Replies carry correlation/session, version2, OFFLINE_ONLY and mayExecuteGuest=false. They are not simulated successful runtime replies. LifecycleV2.syntheticFixture separately models explicit STARTING/RUNNING/STOPPING transitions, tagged simulated=true. A synthetic crash quarantines the model and retains data; it cannot restart. None of these models operates an actual lease or disk.

FrameAssemblerV2 handles canonical out-of-order32KiB chunks into raw BGRA8888 fixtures. It checks session/layout on each call, dimensions <=640x480, exact stride and output length, frame IDs, chunk sizes/offsets/replays and2second incomplete expiry. In this first raw-only slice, the256KiB wire cap also limits total raw pixels;640x480 raw frames exceed that cap and are rejected. No decompressor/compressed codec is implemented. At most2raw buffers including the displayed frame exist per assembler; an injected shared Budget caps aggregate pixel reservations plus256bytes metadata per buffer at16MiB. Share one Budget across the authoritative server. It enforces4newframes/second and1MiB chunk bytes/second per case, including close/reopen attempts. Only complete latest frames are published; replacement discards older partial data. Copy goes into a caller-owned exact-sized buffer. Revoke frees buffers. Closed stream hooks remain bounded; reopen with a fresh session for a new layout/lifecycle. There is no GL upload, Minecraft packet channel or guest framebuffer rendering in this milestone.

GuestInputV2 has typed finite key/button codes and bounded normalized pointer coordinates, a32event queue, shared30events/second per-owner limiter, required focus/session/layout validation and release-all on focus loss/revoke. Events have a fixed <=64byte prospective encoding bound; no input wire serializer or actual guest/host injection exists. Share the Limiter server-wide. Future frame/input integration must preserve BIOS navigation and target guest controls only. Device enum HDD/CD/FLOPPY reserves typed activity names; no synthetic disk sound or real QEMU telemetry is emitted.

RAID remains one aggregate virtual disk in the existing metadata API. Durable ownership/leases, actual byte-policy approval, safe shutdown attachment and crash-consistent backup are prerequisites before a real backend. Block/member removal must not delete data. Copy/import of selected shutdown VMs must close backing/snapshot/ISO/NVRAM dependencies; use-in-place needs separate permission because writes affect originals. No user VM or disk was opened or converted.

Next: connect API2 statuses and bounded synthetic frames/input to the existing shared screen in a separately reviewed milestone, then qualify one exact OS/CPU-specific QEMU/firmware pack and owned no-network TCG guest. No QEMU acquisition, installation, process/guest execution, host configuration, networking or real disk attachment occurred. Windows/Linux/CachyOS/macOS and cross-ISA combinations remain untested. Optional acceleration is separate. A redistributed QEMU pack still needs exact GPL/per-file, library and firmware notices plus corresponding source/patch/build/install material; separate process packaging is not a blanket licence exemption.

Offline fixtures and actual reobfuscated-JAR old/new-addon compatibility are recorded in the release evidence. Synthetic success does not establish live rendering, server interoperability, real backend safety, performance or audible CD playback.
